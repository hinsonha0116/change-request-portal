## A6 Change Management

Welcome to the A6 Change Management portal. This is where you request, track and approve changes to A6 systems, networks, hardware and software.

Every change goes through a review before it's made. That way the people affected know what's coming, risks are looked at in advance, and there's a tested plan to undo the change if something goes wrong.

### Submitting a change request

1. Click **+ Request a New Change** in the portal below.
2. Fill in the details: what's changing, why, where, which systems are affected, when you plan to do it, and whether there will be an outage.
3. Download the **Rollback Plan template** from the request form, fill it in, and attach it. **Every request needs a rollback plan.**
4. Click **Submit**. You'll get a CR number, e.g. **CR-2026-001**. Use it whenever you ask about your request.

You can track your request on the board at any time. You'll only see requests you submitted or that were made on your behalf.

### How a request moves through review

| Change type | When to use it | Route |
|---|---|---|
| **Standard** | Routine, low-risk, pre-approved changes | Requested → Implementation → Close |
| **Normal** | Most changes | Requested → Technical Review Board → Change Advisory Board → Change Authority → Implementation → Post-Implementation Review → Close |
| **Emergency** | Urgent fixes that can't wait for the normal schedule | Requested → Change Advisory Board → Change Authority → Implementation → Post-Implementation Review → Close |

- **Technical Review Board (TRB):** checks the technical plan, testing and rollback plan. If something needs fixing, the request comes back to you with comments.
- **Change Advisory Board (CAB):** reviews the risk, impact and timing.
- **Change Authority:** gives final approval.
- **Implementation:** the change is carried out. The implementer marks it **Completed** when done.
- **Post-Implementation Review (PIR):** confirms the change worked, then the request is closed.

### Schedule of changes

The **Schedule** view shows all planned changes on a calendar. Check it before choosing your dates. A red outline marks a possible clash with another change at the same location or for the same program.
